## 1. 从全部组件提炼的 12 条通用做法

1. **一个组件只讲一件事，5–8 秒。** 进场 0.3–0.6 秒，元素之间错开 0.3–0.6 秒，在第 60% 左右的时间「揭晓」，最后留 1–1.5 秒定格让人看清。
2. **「先灰后亮」是核心语法。** 所有元素先以灰色/压暗出现，讲到谁谁变亮（金/红/紫），讲过的变灰但留在原位——观众随时知道「现在讲到哪」「前面讲过什么」。
3. **永远只有一个主角色。** 图表里只有主角一行/一柱/一块上色，其余全灰。颜色就是指针。
4. **画面跟着口播走。** 念到哪个词，哪个元素出现/点亮（L43 逐词点亮、H102 念到才填、T10j 毛刷跟读）。字幕和动画在同一帧对齐。
5. **先留悬念再揭晓。** 用「???」、打码 XXXX、剪影、空位、问号卡占位，下一句再揭晓（L06 L24 L25 L35 L36 H098 H104）。
6. **数字永远有容器。** 数字不是飘在空中，而是放在数字牌、账本卡、计数器框、圆环里；同一个数字变化时「位置不动只换值」（L15）。
7. **讲过的数字不消失。** 数字牌叠成一摞（L12）、账本卡逐步更新（L19）、旧 logo 变灰留位（L34）。
8. **底图永远是真实画面，压暗 + 模糊。** 小Lin/Fred 财经风格都不用纯色背景：实拍或照片压到 30–40% 亮度做底，前景是一张斜放、微 3D、缓慢推近的卡片。卡片在 5 秒里一直在轻微运动，不静止。
9. **证据要真。** 原文截图、新闻页、公告、报告逐句高亮，旁边配中文翻译和数字牌（L16 L39 L40 H017 H027 H109）。
10. **章节要有导航。** 开头承诺几件事（H025），每章用章节卡（H001/H004/H006…），角落常驻问句或段落名（H101 L48），全片总图反复回来 3–5 次（H116），结尾节点总结（H100）。
11. **比喻要做成动画。** 把抽象概念换成生活物件并让它动起来：汉堡分层（xg015）、百元钞扣成本（H120）、天平称收支（H123）、实习生堆满主页（T01j）、菜谱上锁（T13g）。
12. **开头 1 秒一个新信息。** 成片样片 xg001 前 17 秒换了 12 个画面：实拍快切 → 红色「突发」标签 → 印章大字 → 「两天后」时间卡 → 计数器 → logo 标签 → 大字结论。

## 2. 三套风格对比

| 风格 | 外观 | 优点 | 缺点 | 金融博物馆什么时候用 |
|---|---|---|---|---|
| **小Lin说**（L/H01–27） | 深色模糊实拍底 + 斜放玻璃卡/白纸卡，红=跌、金=主角、蓝=对照，粗黑体标题 | 信息密度高、像财经杂志；卡片斜放有纵深；纸质卡（L10 L11 L41）有档案感 | 每个组件都要做 3D 透视和背景素材，工作量大；全片都用会单调 | **主力风格**。历史档案、数据、股价、公司结构 |
| **Fred 财经**（H001–H127） | 纯黑底 + 金色主色 + 白字，极简，几乎没有装饰 | 干净高级、文字永远清楚、组件最全（转场、章节、开场、结尾全套） | 黑金容易显得冷、单调；不压实拍时缺少「场景感」 | 章节卡、转场、数字/图表、结尾金句；适合「讲道理」的段落 |
| **教程白底紫**（视觉库） | 白底、黑色胶囊、紫色唯一强调色、真实截图窗口 | 明亮、亲和、截图讲解很清楚 | 偏工具教程，金融历史题材显得轻 | 只借手法（逐句跟读、骨架屏、成绩单打勾、章节过渡）；换成本期配色再用 |

> 注意：A 股语境红涨绿跌（项目已有规则）。小Lin/Fred 的「红=跌」是美股习惯，用到 A 股/港股时要反过来。

## 5. Remotion 实现参数（从样片量出来的）

- 组件时长：5–8 秒；总图类 10–25 秒（H116、H120）。
- 进场：0.3–0.6 秒，ease-out；元素错开 0.3–0.6 秒（stagger）。
- 揭晓点：组件时长的 55–65% 处；揭晓后定格 ≥1.2 秒。
- 卡片持续运动：5 秒内缩放 1.00 → 1.04，或绕 Y 轴 −8° → −4°，永不完全静止。
- 背景：实拍/照片，亮度 30–40%，高斯模糊 6–12px，可加暗角。
- 「先灰后亮」：非焦点元素 opacity 0.35–0.45 或灰度 100%；焦点元素放大 1.05–1.15 并上色。
- 快切：实拍快切每段 0.2–0.8 秒，配 0.1–0.2 秒叠化。
- 数字滚动：0.8–1.5 秒，老虎机版每位错开 0.15 秒停。
- 字号：标题 ≥ 画面高度 5%，关键数字 ≥ 12%；字幕在底部 85–90% 高度处。
- 配色：一个主强调色（金 / 红 / 紫选一）+ 一个对照色 + 灰阶；每期按主风格换强调色，不要每期都黑金。

## 7. FredTalk 官方制作方法（来自 GitHub 仓库的 skill，适配到金融博物馆）

> 仓库里的 `fred-remotion-output` 是 Fred 自己每期在用的制作 skill。外观规则（白底、黑胶囊、紫色）是教程风格专用的，**不照搬**；下面只取能直接用到我们片子的**方法**。

### 7.1 最重要的一句话
好坏对照样例的总结：差的做法是「这句话配一个组件 / 配一段相关素材」；好的做法是「**这句话让观众看见哪个对象怎么变**」，再用组件动作和素材把这个变化演出来。

动手写每段代码前问三个问题，有一个答不上就先改设计：
1. 关掉声音只看画面，观众能不能说出这一段发生了什么变化？
2. 口播提到的每个名词、数字、动作，画面里看不看得到、看不看得清？
3. 这一段的对象，是不是接过了上一段的对象、又交给了下一段？

### 7.2 每段先写「逐句动作表」
每句写五样：**对象 → 变化 → 证据在哪 → 观众看哪 → 交给谁**。例：「1637 年 2 月，价格一夜崩了」→ 对象：价格折线 → 变化：红线从高点垂直掉下、跌幅大字砸出 → 证据：当年拍卖价格表 → 观众看：跌幅数字 → 交给：下一段的空郁金香球茎。

### 7.3 场景为本期重写，复用到「动作层」
- 不要把组件原样串起来：每个组件都有自己的开场和收尾，串起来会不停「重置」观众注意力。
- 只拆组件的**动作和对象关系**，为本期内容重写场景；每个场景文件第一行注释写「动作来自哪个组件」。
- 长段落靠**一条动作链**撑住：一个对象持续换角色（例：庞兹的邮票券 → 变成金币 → 金币从下层流向上层 → 金字塔摇晃 → 倒塌）。

### 7.4 段与段之间：交接表
- 不用淡入淡出、整屏平移、PPT 式划走。**上一段末帧 = 下一段首帧**：同一个对象、同一位置、同一尺寸，靠一个连续动作交出去。
- 写代码前列交接表：| 接缝 | 上段末态 | 下段首态 | 动作 | 音效 |
- 常用交接：胶囊放大成黑幕再开窗；卡片变形成窗口；页面压成一条线再展开；三张卡聚拢成一个结论；前后景深交换（旧的后退缩小，新的从近处压上来）。
- 交接对象两侧共用同一个绘制组件，不只共享坐标。
- 检查接缝要看前后各 0.5 秒的动态，不只比两张静帧。

### 7.5 动效写法（Remotion）
- 每一帧的样子都由 `t = 帧号 / fps` 算出来；不用 CSS transition / keyframes。动画只改 transform、opacity、clipPath，少量 blur。
- 曲线：进入/落定 `bezier(.22,1,.36,1)`；搬移/缩放 smoothstep；章节擦出 `bezier(.65,0,.2,1)`；相机 quintic（两端零速度）。
- **入场默认无过冲**（会显得「抖一下」）；只有明确要「砸下来」才用一次回弹。
- **先算终态版式，再让东西走到终态**：字号 = min(上限, 可用宽 / 文字宽)，对象从起始框插值到终态框，换长文案也不跳位。
- **同一个进度驱动多个属性**：位移、缩放、透明度、圆角一起开始一起结束，看起来才是同一个物体。
- **对象连续**：圆点 → 圆 → 胶囊 → 徽章是同一个 div 变形，不要「消失再出现」。
- **用 clipPath 擦出代替淡入**：轮廓清楚、方向明确，不会半透明叠字。
- 逐字打出：整句先按终态排好，未打到的字透明占位，打字时整行不左右挪。
- 划掉：先把字退灰，再让一条线沿中线生长。
- 景深退后 = 缩小 0.92–0.96 + 失焦 12–19px + 半透明蒙版，三者同一进度；还要读的表格失焦 ≤4px。
- 相机：移动约 0.6 秒，停稳阅读 0.85–1.65 秒，推近常见 1.3–1.6 倍，按「目标整行在画内」反算倍数；不全程慢漂。
- 依次出现按口播 cue；没有 cue 时间隔 0.5–1.2 秒，不机械等距；同组小件错开 0.045–0.075 秒。
- 典型时长：单项进入 0.38–0.42 秒；胶囊打开 0.8 秒；汇聚 0.72 秒；常规组件 5 秒；快过渡 1–3 秒；主体 0.3 秒内开始出现；结尾至少 0.6 秒稳定。
- 渲染必须确定：不用 Math.random，伪随机用固定种子。

### 7.6 强调方式
- 指出画面某处：**局部压暗（其余压到 0.6）**、阴影抬起、毛刷从左到右刷过；不用彩色框，尽量不用黑框。
- 毛玻璃（材料退后、结论在前）要用但别做成同一个套路：相邻几处不要连用同样子；白底上别压全屏黑玻璃（发灰）。
- 高亮要停到那句口播说完，至少 1.5 秒。
- 几项并列信息：一张卡逐行点亮，不拆成几枚漂浮小胶囊。
- 段尾不要整页半透明溶解：要么整张退后沉出画面，要么由同一对象接走。

### 7.7 排版底线（每张关键帧都查）
- 关键内容 y ≤ 900（1080 画布），给字幕留位；左右至少 80px。
- 主体要够大、要居中，不要「上重下空」：主体占 y 200–880；卡片一张张加入时每一步整组重新居中。
- 一屏超过 4 块信息就改成镜头逐块推近：先全景 0.6 秒，再逐块推近停稳 1–1.5 秒。
- 一句大字停超过约 2 秒，就要带出第二个变化。
- 推近不截字：要读的内容左右至少留 24px；会翻动的数字按最宽值留位。
- 口播提到数量，画面就给出真实数字，放在原文位置。
- 口播提到的每个名词，画面上都要出现；素材里没有就重建示意，不随便放一段「相关的」视频。

### 7.8 去重
- 讲解结构类组件（路线图、方法卡、问答）全片只出现一次；运镜套路也要去重。
- 章节页每期换着用，不要每次都是同几种。
- 出关键帧前把全片用到的组件列一张表查重复。

### 7.9 开头和结尾
- 第一秒就给最有冲击的信息（例：第 0 帧数字就从 0 滚到位），0.5 秒内到位，直接进入真实内容，不空滚。
- 结尾默认把画面上的卡片和胶囊往中间收，合成一枚结论，停稳到段尾。

### 7.10 音效（和我们现有规则合并）
- 一个主动作一声，挂在动作开始或落定那一帧；每个组件通常 1–4 声。
- 出现 = pop；推近/接管 = woosh；遮罩刷出 = 短 whoosh；让位/展开 = slide；真实点击 = click；打字只覆盖打字区间。
- 「叮」成功声和数字滚动声全片各只留 1–2 处，其余换成 woosh / pop。
- 和项目已有规则合并执行：同一秒最多 1 个音效、关键处音效明显大声（项目规则优先）。

### 7.11 出片前自检（Fred 的 10 条 + 我们的）
1. 录屏/素材有没有整窗干播、慢推、纯滚动超过 2 秒、定格凑时长？
2. 讲到动作时，画面有没有对应的状态变化？
3. 组件有没有重复？
4. 强调有没有用框？毛玻璃是不是总一个样？
5. 排版：居中、y ≤ 900、不出画、推近后字完整？
6. 口播里的数量有没有真实数字上屏？
7. 时间不够时，有没有保住组件最后的结果动作（压缩前面而不是截掉高潮）？
8. 口播里每个名词画面上都有吗？
9. 能用真实画面的，有没有用了自绘示意代替？
10. 关掉声音，能不能看懂这一段发生了什么？
